# CLAUDE.md — MuoviTech / TurboCollector Knowledge Hub

Instructions for Claude Code working in `C:\Mouvitech-project`. Read this before
making changes.

## What this project is
An internal **"company brain"**: a multimodal RAG chatbot that lets the sales team
self-serve technical questions about the **TurboCollector** product and geothermal
energy, instead of interrupting the project engineers. Answers come from the
company's training videos, meeting recordings, slide decks, the marketing video
script, and technical correlations — using both **what was said** (transcripts)
and **what was on screen** (video keyframes).

## How to run the chatbot (Windows PowerShell)
```powershell
cd C:\Mouvitech-project\chatbot
.venv\Scripts\python.exe ingest.py                 # rebuild vector DB (run after chunks.jsonl changes)
.venv\Scripts\python.exe -m streamlit run app.py   # launch the app
```
Stack: `streamlit`, `chromadb`, `sentence-transformers` (embeddings,
`all-MiniLM-L6-v2`), `anthropic` (answering model, vision-capable).

## Chunk schema (chunks.jsonl)
One JSON object per line: `id`, `source`, `source_type` (`slides` | `video_script`
| `formulas` | `key_facts` | `glossary` | `transcript` | `visual_frame`), `title`,
`text` (transcript + OCR of on-screen text), `word_count`, `quality`
(`high` = documents, `low` = ASR/OCR), optional `frames[]`
(`{image, timestamp, start_sec, on_screen_text}`), and `metadata`
(`file_id`, `start_sec`, `end_sec`, `timestamp`, `n_frames`, `raw_asr`).
- `ingest.py` embeds `text`, stores `frames` as `frames_json` in Chroma metadata,
  and drops `raw_asr` from what gets embedded.
- `app.py` retrieves top-k, loads the referenced images from
  `..\knowledge_base_multimodal\images\`, and sends **text + images** to Claude.

## How the knowledge base was built (to extend it with new videos)
Pipeline, per source video:
1. `ffmpeg` extract 16 kHz mono audio.
2. **Transcribe** with Whisper base (int8) via `sherpa-onnx` in ~28s windows,
   skipping near-silent windows; the Polish clip is translated to English.
3. **Keyframes**: sample frames (every ~15–45s, denser for screen recordings),
   de-duplicate with a perceptual hash so each frame is a distinct on-screen state.
4. **OCR** each frame with `tesseract`; fold on-screen text into the chunk `text`.
5. **Chunk**: merge ~3 transcript windows per chunk; attach frames whose timestamp
   falls in the chunk's span; clean recurring ASR mishears
   (geothermal, TurboCollector, MuoviTech, Reynolds, Nusselt) and collapse
   repetition loops.

## Environment gotchas (important)
- **HuggingFace is blocked on this network.** Do not add code that downloads models
  from huggingface.co at runtime — it will fail. The `all-MiniLM-L6-v2` embedding
  model is already cached locally. Whisper/other models were fetched from **GitHub
  release assets** (e.g. `github.com/k2-fsa/sherpa-onnx` releases), which the network
  **does** allow; use that route if you need a model.
- `app.py` uses `CLAUDE_MODEL = "claude-sonnet-5"` — must be a valid, **vision-capable**
  model id for the configured API key. If an API call fails on the model name, fix it here.
- Transcript/OCR chunks are `quality: "low"` — the app is told to prefer `high`
  (document) chunks and to read on-screen values off the screenshots.
- Keep the real `ANTHROPIC_API_KEY` out of git (`.env` is gitignored).

## Conventions
- The knowledge base is a **build artifact** — regenerate it rather than hand-editing
  `chunks.jsonl`. Re-run `ingest.py` whenever it changes.
- Cite sources in answers as `[source: <source>, <timestamp/detail>]`.
- Keep answers grounded in retrieved context + screenshots only; never invent product facts.
